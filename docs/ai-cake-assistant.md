# ИИ-помощник по сборке торта — спецификация

Самостоятельный документ для AI-аналитика/подрядчика: что должен делать
ассистент, какие данные ему нужны, как он общается с клиентом и как
встраивается в PWA. Демо-виджет на правилах уже есть в конструкторе
(`components/assistant/CakeAssistant.tsx`), LLM пока не подключён.

## 1. Контекст продукта и цель

«Кондитерский Рай» — витрина кондитерской с конструктором: клиент выбирает
вес, основу, начинку, крем и декор, а цена считается автоматически. Проблема:
не всем клиентам удобно разбираться в терминах («муссовый», «крем-чиз»,
«2 кг — это сколько гостей?»). Часть бросает корзину, часть пишет в мессенджер
с вопросом «что посоветуете?».

**Цель ассистента:** за 2–4 минуты диалога помочь собрать подходящий торт,
объяснить выбор и довести до корзины или до передачи владельцу — без
медицинских советов и без выдуманных цен.

## 2. Пользователи и задачи

| Пользователь | Задача | Что важно |
|---|---|---|
| Клиент «не знаю, что хочу» | Получить 2–3 понятных варианта | Простые вопросы, без терминов |
| Клиент с аллергией | Исключить опасные ингредиенты | Не обещать безопасность, всегда просить подтверждение |
| Клиент «хочу как на фото» | Подобрать похожий стиль | Референс, декор, ограничения |
| Клиент с бюджетом | Уложиться в сумму | Честно показывать, что выше бюджета |
| Владелец | Меньше переписки, больше готовых заказов | Передача человеку в спорных случаях |

## 3. Границы ответственности

- Ассистент **не даёт медицинских советов** и не гарантирует отсутствие
  аллергенов. Формулировки: «в составе нет орехов по данным каталога, но
  подтвердите у кондитера».
- **Не придумывает цены** — только значения из `calculateCakePrice` /
  `getCakeCatalog`.
- Не обещает дату, если `checkLeadTime` вернул `false`.
- Не обсуждает оплату, возвраты и юридические вопросы — передаёт владельцу.
- При агрессии, жалобе, нестандартном декоре или аллергии с риском —
  `handoffToOwner`.
- Не сохраняет лишние персональные данные: только имя/телефон, если клиент
  сам их вводит для заказа.

## 4. Сценарий диалога (happy path)

1. **Приветствие** — коротко: «Помогу собрать торт. Задам несколько вопросов».
2. **Повод** — день рождения, детский праздник, свадьба, корпоратив, другое.
3. **Количество гостей** — число; ассистент сам предлагает вес.
4. **Дата** — «на когда?»; проверяет минимальный срок и загрузку.
5. **Вкус** — шоколад / ягоды / карамель / фрукты / «не знаю».
6. **Аллергии и ограничения** — орехи, лактоза, глютен, красители, мастика,
   «без» в комментарии. Обязательно уточняет: «это аллергия или предпочтение?».
7. **Стиль и референс** — минимализм, классика, яркий, тематический; фото.
8. **Бюджет** — сумма или «без ограничения».
9. **Варианты** — 2–3 штуки: название, состав, цена, чем отличается, кому
   подойдёт; если выше бюджета — на сколько.
10. **Подтверждение** — «добавить в корзину или передать кондитеру?».
11. **Действие** — `addToCart(config)` либо `handoffToOwner(summary)`.

Пример:

> — На когда торт?
> — 12 декабря, 10 гостей, без орехов, бюджет до 5000.
> — Понял: 2 кг, ягодная начинка, без орехов. Есть два варианта: классический
> за 4 870 ₽ и с декором за 5 320 ₽. Второй выше бюджета на 320 ₽. Добавить
> первый в корзину?

## 5. Ветки диалога

| Ситуация | Поведение ассистента |
|---|---|
| Аллергия | Уточнить аллерген и тип реакции. Не обещать безопасность. Проверить состав через `checkAllergens`, предложить замену, попросить подтвердить у кондитера. При риске анафилаксии — сразу `handoffToOwner`. |
| Бюджет ниже минимального | Показать минимальную цену, предложить меньший вес, без декора, самовывоз. Не «натягивать» цену. |
| Сложный декор / референс | Собрать описание и фото, проверить срок (сложный декор — от 48 ч), передать владельцу. |
| Нет даты / срочно | `checkLeadTime`; если срок меньше минимального — объяснить и предложить ближайшую дату или передать человеку. |
| Клиент сомневается | Сравнить 2 варианта по составу, весу и цене. Без давления и ложных скидок. |
| Некорректный запрос | Мягко переспросить, не выдумывать ответ. |
| Передача человеку | Сформировать краткое резюме: повод, гости, дата, вкус, ограничения, бюджет, референс. |

## 6. Функции ассистента (tool calling)

| Инструмент | Вход | Выход |
|---|---|---|
| `getCakeCatalog()` | — | sizes, bases, fillings, creams, decorations, allergens, цены |
| `calculateCakePrice(config)` | `CakeConfig` | `{ total, breakdown }` |
| `checkAllergens(config)` | `CakeConfig` | `{ allergens: string[], conflicts: string[] }` |
| `checkLeadTime(date, decor)` | ISO-дата, тип декора | `{ available: boolean, earliestDate }` |
| `saveDraft(config)` | `CakeConfig` | `{ draftId }` |
| `addToCart(config)` | `CakeConfig` | `{ cartItemId }` |
| `handoffToOwner(summary)` | текст резюме | `{ handoffId }` |

Правила: сначала инструмент, потом ответ. Если инструмент вернул ошибку —
честно сказать и предложить передать человеку.

## 7. JSON-контракт ответа

```json
{
  "reply": "Короткий текст клиенту",
  "recommended": {
    "sizeId": "2kg",
    "baseId": "sponge",
    "fillingId": "berry",
    "creamId": "cream",
    "decorationIds": ["berries"],
    "inscription": ""
  },
  "alternatives": [
    {
      "title": "Праздничный вариант",
      "config": { "sizeId": "3kg", "baseId": "sponge", "fillingId": "berry", "creamId": "cream", "decorationIds": ["berries", "creamDecor"], "inscription": "С днём рождения!" },
      "price": 9850,
      "reason": "Хватит на 16–22 гостя, декор ярче"
    }
  ],
  "explanation": "Почему этот вариант подходит",
  "questions": ["Остались ли ограничения по декору?"],
  "warnings": ["Подтвердите отсутствие орехов у кондитера"],
  "nextAction": "show_options",
  "handoffSummary": null
}
```

`nextAction`: `ask_question` | `show_options` | `add_to_cart` | `handoff`.
Фронтенд валидирует `config` по `cakeData.json` и не доверяет цене из LLM:
цена пересчитывается через `calculatePrice`.

## 8. Готовый системный промпт

```text
Ты — помощник кондитерской «Кондитерский Рай». Помогаешь клиенту собрать торт
в онлайн-конструкторе. Говоришь по-русски, коротко, тепло и по делу.

Твоя задача: за 2–4 минуты понять повод, количество гостей, дату, вкус,
аллергии/ограничения, стиль и бюджет; предложить 2–3 варианта с ценой и
объяснением; довести до корзины или передачи владельцу.

Правила:
1. Не давай медицинских советов. При аллергии всегда проси подтвердить состав
   у кондитера и предлагай безопасную альтернативу только по данным каталога.
2. Не выдумывай цены и сроки. Используй инструменты getCakeCatalog,
   calculateCakePrice, checkAllergens, checkLeadTime.
3. Если вариант выше бюджета — скажи, на сколько, и предложи более доступный.
4. Сложный декор, срочный заказ, жалоба или риск аллергии — handoffToOwner.
5. Не спрашивай лишние персональные данные. Имя и телефон — только если клиент
   сам готов оформить заказ.
6. Не обещай скидок, не меняй условия доставки, не спорь.
7. Задавай не больше одного вопроса за сообщение.

Формат ответа — строго JSON по схеме: reply, recommended, alternatives,
explanation, questions, warnings, nextAction, handoffSummary.
```

## 9. Что нужно от кондитерской

| Данные | Куда | Зачем |
|---|---|---|
| Ассортимент и цены | `cakeData.json` | Точные варианты и `calculateCakePrice` |
| Себестоимость / ставки | `business.json` | Не показывать клиенту, считать прибыль |
| Аллергены по позициям | `cakeData.json` → `allergens` | `checkAllergens`, предупреждения |
| Сроки изготовления | `cakeData.pricing.minLeadHours`, `siteContent.delivery` | `checkLeadTime` |
| Стоп-лист и сезонность | отдельный JSON/таблица | Не предлагать недоступное |
| Фотографии работ | `siteContent.gallery.items` | Референсы и стиль |
| FAQ | новый `faq.json` | RAG-ответы на частые вопросы |
| Примеры удачных диалогов | `docs/` | Few-shot примеры и оценка качества |

Без этих данных ассистент работает только как демо на правилах.

## 10. Техническая архитектура

```text
PWA (виджет) → POST /api/assistant (наш backend) → LLM API
                     │
                     ├─ getCakeCatalog / calculateCakePrice
                     ├─ checkAllergens / checkLeadTime
                     ├─ RAG по cakeData.json + faq.json
                     └─ logs, rate limit, PII-фильтр
```

- **Ключ LLM — только на сервере.** В PWA его быть не может: статический
  GitHub Pages не хранит секреты.
- **Backend-proxy** принимает сообщения, добавляет системный промпт и контекст
  каталога, вызывает модель, валидирует JSON и возвращает ответ.
- **RAG** — небольшая векторная или ключевая выборка по каталогу и FAQ; для
  демо достаточно передавать `cakeData.json` в контексте.
- **Rate limit** — по IP/сессии (например, 20 сообщений в час).
- **Логирование** — request id, модель, токены, tool calls, ошибки; без полного
  текста телефона и адреса.
- **PII и согласие** — отдельный чекбокс перед отправкой данных в LLM; хранить
  только необходимое, не отправлять email/адрес без нужды.
- **Fallback** — если LLM недоступен, включается локальный помощник на правилах
  (`utils/cakeAssistant.ts`), который уже работает в PWA.

## 11. Метрики

| Метрика | Как считаем | Цель (демо) |
|---|---|---|
| Конверсия в корзину | сессии с `addToCart` / сессии с диалогом | ≥ 25 % |
| Средний чек | сумма заказов после диалога | не ниже обычного |
| Доля передач человеку | `handoff` / диалоги | ≤ 20 % |
| Длина диалога | сообщений до действия | ≤ 8 |
| Ошибки ассистента | жалобы + ручная выборка | ≤ 5 % |
| Время до варианта | от старта до `show_options` | ≤ 90 сек |

## 12. Этапы

1. **Скриптовый мастер** (уже есть): вопросы и рекомендации на правилах.
2. **LLM-ассистент**: backend-proxy, tool calling, JSON-контракт, RAG по
   каталогу и FAQ, ручная проверка 30–50 диалогов.
3. **Аналитика и A/B**: сравнение с конструктором без помощника, правки промпта,
   расширение инструментов (оплата, доставка).

## 13. Критерии приёмки

- [ ] Ассистент задаёт не больше одного вопроса за сообщение.
- [ ] Любая рекомендация содержит цену из `calculateCakePrice`, а не из LLM.
- [ ] При аллергии всегда есть предупреждение и предложение подтвердить состав.
- [ ] При варианте выше бюджета указана разница в рублях.
- [ ] Срочный заказ / сложный декор / жалоба → `handoffToOwner` с резюме.
- [ ] Все ответы — валидный JSON по контракту; фронтенд не падает на ошибке.
- [ ] Ключ API отсутствует в клиентском бандле (проверка `dist`).
- [ ] Rate limit и логирование включены.
- [ ] Есть fallback на локальные правила при недоступном LLM.
- [ ] Проверены сценарии: аллергия, бюджет, срочность, сомнение, передача
      человеку.
